## What a wrong assumption produces

The assignment is built so that guessing a rule gives a believable, different number. When a
student's agent reports one of the figures in the right-hand column, this is the cause.

| Mistake | Symptom |
|---|---|
| Averaging raw `marks` instead of percentages (AR-1) | department averages several points too low |
| Treating absent as zero in an average (AR-3) | averages slightly too low |
| Using 40 % as the pass mark for labs (AR-2) | pass percentages too high, most visibly for lab papers |
| Leaving absentees out of the pass-percentage denominator (AR-5) | pass percentages slightly too high |
| Comparing raw `marks >= 40` | pass percentages far too low (a lab mark can never exceed 50) |
| Counting empty attendance as a shortage (AT-3) | too many students flagged for academic attention |
| Ignoring attendance in 'academic attention' (SS-1) | far too few students flagged |

## Public evaluation questions (students have these)

### P1 - sql

> Which department has the highest average percentage of marks, and what is that average?

**Expected:** 68.47 (average percentage of CSE); CSE / Computer Science and Engineering.

```sql
SELECT department, ROUND(AVG(marks * 100.0 / total_marks), 2) AS average_percentage FROM student_performance GROUP BY department ORDER BY average_percentage DESC
```

AVG ignores NULL marks, which is what AR-3/AR-4 require. Averaging raw marks instead of percentages gives a different (wrong) figure because labs are out of 50.

### P2 - policy+sql

> What is the pass percentage of each department, and which department has the lowest?

**Expected:** 90.63 (pass percentage of ME); ME / Mechanical Engineering; rule retrieved: AR-2.

```sql
SELECT sp.department, ROUND(100.0 * COUNT(*) FILTER (WHERE NOT (sp.marks IS NULL OR sp.marks * 100.0 / sp.total_marks < CASE WHEN sd.subject_type = 'Lab' THEN 50 ELSE 40 END)) / COUNT(*), 2) AS pass_percentage FROM student_performance sp JOIN subject_details sd ON sd.subject = sp.subject GROUP BY sp.department ORDER BY pass_percentage
```

The trap: laboratory papers pass at 50 %, not 40 % (AR-2). An agent that assumes 40 % for everything reports higher pass percentages. Absent records stay in the denominator (AR-5).

### P3 - policy+sql

> How many students need academic attention in at least one subject of semester 4?

**Expected:** 99 (students flagged in semester 4); rule retrieved: SS-1.

```sql
SELECT COUNT(DISTINCT sp.student_id) FROM student_performance sp JOIN subject_details sd ON sd.subject = sp.subject WHERE sp.semester = 4 AND ((sp.marks IS NULL OR sp.marks * 100.0 / sp.total_marks < CASE WHEN sd.subject_type = 'Lab' THEN 50 ELSE 40 END) OR sp.attendance < 75)
```

SS-1: not passed (including absent) OR recorded attendance below 75. NULL attendance is never a shortage - `attendance < 75` is NULL, hence false, for those rows.

### P4 - sql

Tests that the load kept NULLs as NULLs (DD-6). A loader that wrote 0 or '' makes this 0.

### H5 - policy+sql

> How many students are on the Dean's merit list for semester 4, and who has the highest aggregate?

**Expected:** 8 (students on the semester 4 merit list); Esha Varghese / CS24048; rule retrieved: SS-6.

```sql
SELECT sp.student_id, sp.student_name, ROUND(SUM(COALESCE(sp.marks, 0)) * 100.0 / SUM(sp.total_marks), 2) AS aggregate FROM student_performance sp JOIN subject_details sd ON sd.subject = sp.subject WHERE sp.semester = 4 GROUP BY sp.student_id, sp.student_name HAVING SUM(COALESCE(sp.marks, 0)) * 100.0 / SUM(sp.total_marks) >= 80 AND BOOL_AND(NOT (sp.marks IS NULL OR sp.marks * 100.0 / sp.total_marks < CASE WHEN sd.subject_type = 'Lab' THEN 50 ELSE 40 END)) AND BOOL_AND(sp.attendance IS NULL OR sp.attendance >= 85) ORDER BY aggregate DESC, sp.student_id
```
